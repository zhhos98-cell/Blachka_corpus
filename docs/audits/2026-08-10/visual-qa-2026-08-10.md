# Visual QA audit — 2026-08-10

Working assumption: every visible element may have an alignment, spacing, hierarchy, interaction, or layering problem until checked in context.

## Reference patterns

### Apple HIG
Use focus/hover to confirm the target before activation. Large focusable items can gain depth or lift, but motion should remain brief, precise and optional. Pointer interactions should preserve familiar click/tap activation and comfortable hit regions.

References:
- https://developer.apple.com/design/human-interface-guidelines/focus-and-selection/
- https://developer.apple.com/design/human-interface-guidelines/pointing-devices
- https://developer.apple.com/design/human-interface-guidelines/motion

### Rijksmuseum / V&A
Separate discovery, search, thematic browsing and object reading. Do not make every page behave like a database form. Image-led browsing can be visually rich while the record page stays information-led.

References:
- https://www.rijksmuseum.nl/en/collection/discover
- https://www.vam.ac.uk/collections
- https://www.vam.ac.uk/info/explore-the-collections/

### MoMA
Search is primary; filters are available but progressive. Large collection counts do not require every filter or statistic to be visible at once.

Reference:
- https://www.moma.org/collection/

## Counter-patterns for this project

### Aggregator density
The Smithsonian Collections Search Center is appropriate for a very large heterogeneous corpus, but its many pre-search scope controls, category choices and counts would be excessive here. The Blaschka site should not imitate an aggregator dashboard.

Reference:
- https://collections.si.edu/search/

### Decorative motion without state meaning
Avoid movement whose only purpose is to look active. Hover may preview; click activates. Scroll motion should be section-level rather than row-level. `prefers-reduced-motion` must keep every route usable.

### Divider accumulation
A bordered group containing ruled rows and ruled headings is usually one separator too many. Prefer whitespace and optical alignment.

## Pass 1 — Cases directory

Previous problem: the ten-case directory read as a database index. It was efficient but visually flat and gave no strong focus state.

Current direction: ten-panel wall. Desktop pointer/focus previews the documentary bridge with a 3D flip; click remains the standard activation and jumps to the case. Existing exact local images are reused where already present. Other panels remain documentary/typographic screens rather than borrowing unrelated object photographs. Touch layouts do not depend on hover.

QA checks:
- 1920/1440: five columns × two rows should read as one wall, not ten isolated cards.
- 1024: three-column reflow must preserve rhythm.
- 768/430/390: two-column touch layout; no information required only from hover.
- Check flip does not clip into neighboring tiles.
- Check focus outline remains visible.
- Check thumbnail loading does not change tile geometry.

## Pass 1 — Bibliography

Previous problem: checkbox + separate year column + citation column pushed the reading axis too far right and made the list look mathematically aligned but optically displaced.

Current direction: two-column row. Checkbox occupies a narrow utility gutter. Year is part of the citation block and sits immediately above the citation. The reading axis stays close to the page left edge; all bibliography content is explicitly left-aligned.

QA checks:
- Toolbar, Zotero line, `Bibliography` heading and reading list should share the same left axis.
- No bordered toolbar container.
- No rule directly below every entry.
- Long citations should remain within a readable measure rather than stretching to the full viewport.
- Mobile export controls may scroll horizontally, but citation text must never do so.

## Screen-by-screen queue

For every screen ask:
1. Is any element within ~10–14px of an edge without a functional reason?
2. Are things that belong together separated by too much space?
3. Are unrelated things enclosed by one border/surface?
4. Is anything mathematically centred but optically high/low or left/right?
5. Does the user know the next action without reading explanatory UI copy?
6. Is a statistic, badge, line, watermark, animation or label carrying real information?
7. Does removing one visible element improve the screen?

Order:
1. Home hero
2. Home project + origin
3. Home featured cases
